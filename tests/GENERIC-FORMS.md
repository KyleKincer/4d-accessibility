# Forms without a bridge area

An application's own forms that have no bridge area get a baseline description from the native plugin alone, with no host change. An integrated form, with its lifecycle area, keeps the bridge's complete description; the plugin leaves it to the bridge.

4D draws each form object into a layer named after the object, and the plugin reads the text it draws there. When it starts, the plugin indexes the open project's form definitions, `Project/Sources/Forms` and `TableForms`, in the background. A window is matched to the form that holds most of its object layers. Too few objects, or two equally likely forms, leave the window untouched. The plugin then publishes, in reading order:

- **buttons** and picture buttons by their drawn titles, their definition's titles or their help tips. Otherwise a button is named by the words of its object name, without a button prefix or suffix (`pbNextRecordBtn` is Next Record, `btn_Stop` is Stop), or else by its picture file (`Gear_Icon.png` is Gear). A button with 4D's default name (`Button1`, `Picture Button`) and no picture is not published, nor is an invisible button, which draws nothing and serves as a keyboard shortcut or a click area;
- **captions** as static text;
- **inputs** as text fields with their drawn values and placeholders. Each is labelled by its help tip, or by the caption on its left or just above it;
- **checkboxes and radio buttons** by their titles. Their state is read from the image 4D draws, in the standard style: macOS fills a checked box or chosen button with the accent color. With a gray accent color, or a custom style, the state is not reported;
- **drop-down lists** as pop-up buttons showing their drawn values;
- **tab controls** as one radio button per tab, named by the label 4D draws in its segment with HIToolbox (identifiers such as `axb/form/tabPages/Notes`). The chosen tab is the segment macOS draws lighter than the others' track; when no segment stands out, no tab reports a state. Pressing a tab is an ordinary click on its segment, so the tab control's own action, such as going to a page, runs;
- **list boxes** as tables of their visible rows, labelled by their help tip or caption. A list box with neither is named by the words of its object name, without a list prefix or suffix: `listboxManufacturers` is Manufacturers, `lb_sales_limits` is Sales limits and `SourceLB` is Source. 4D's default names, such as `List Box1`, name nothing. 4D draws every visible cell's text into one image; each row is a baseline, and each text belongs to the column that holds it. The visible columns are found between the separator lines 4D draws in the titles' band, since an application can hide and resize columns at run time. Each column's title is the one 4D draws in its header, which its GUI framework draws with HIToolbox's themed text, so a column the application renamed, hid or resized keeps its drawn title. Where no title is drawn, the definition's title is used, matched in order by width; a column drawn at another width than defined, which could be a different column, is left unnamed rather than misnamed. A row's selection is read from the accent color 4D fills it with; pressing or selecting a row is an ordinary click on it. VoiceOver selects the row its cursor reaches, as in AppKit's tables, and a row already selected is not clicked again. A list box longer than its box scrolls by a page when the scroll bar 4D draws in it shows more rows: the table names `AXScrollDownByPage` and `AXScrollUpByPage`, and the table, its rows and its cells offer Scroll down and Scroll up in VoiceOver's actions menu (VO-Command-Space). A page keeps one row, the last whole row moving to the top. The scroll is a mouse-wheel event at the list box, as 4D receives from the mouse, so it changes no selection and runs no object method.

A page subform publishes its own form's objects in its place, in the same way, with identifiers under the subform's name (for example `axb/form/search/btnGo`). Its form can be one of the project's, or a component's: the plugin also indexes the forms of the project's components and of those 4D includes, reading each component's archive (`.4DZ`, a zip) directly. 4D Widgets' search picker, date button, date entry and date picker set their prompts from their methods, so the plugin names their search field "Search", the magnifier "Search options", and their calendar, step and month buttons "Choose date", "Increase", "Decrease", "Previous month" and "Next month" (the date widgets without acceptance yet). Component forms are only used for subforms; they never match a window. An object is published and clicked within the part its subform shows.

Each press is an ordinary click on the object, so 4D runs its own handling exactly as for the mouse. A drop-down opens 4D's native menu. Writing an input's value clicks into it, deletes its text and types each character; focusing an input clicks into it, so typed keys enter it. Typing is announced as text edits.

4D's keyboard focus is reported as the application's focused element. 4D's form view is the window's text-input client, and the first rectangle of its selection is where its focus is: the caret in a field, the top left corner of a list box. The object there is focused, even when its form hides its focus ring, as many applications do on list boxes. macOS also draws the focus ring, translucent in the accent color, just outside the focused control in the margin 4D leaves in its layer, so the plugin finds the ring on fields, drop-down lists, list boxes, checkboxes and radio buttons. When Tab or Shift-Tab moves 4D's focus, the newly focused object becomes the focused element and assistive technologies are told, so VoiceOver follows it. Buttons have neither a ring nor a caret, so the plugin also reads the object 4D's form record names as focused, which covers buttons. That record is private to 4D: each read is checked, a name that is not one of the window's objects is ignored, and the caret and rings decide when the record can't be read.

Picture buttons, group boxes and combo boxes are published as buttons, captions and text fields in the same way, without acceptance yet. Localized and computed titles (`:xliff:…`, `<variable>`) are not used as labels. A list box publishes the rows it draws, paging to the others, and their cells are read-only; list subforms, pictures, hierarchical lists, web areas and plugin areas are not yet described this way. Integrate a form through its [lifecycle area](../skills/4d-accessibility/references/AREA-INTEGRATION.md) for its complete description, including grids, values, states and focus.

## Test

```sh
python3 test_generic_form_fixture.py --server /path/to/4D\ Server.app --baseline
python3 test_generic_form_fixture.py --server /path/to/4D\ Server.app --run
python3 test_generic_form_fixture.py --server /path/to/4D\ Server.app --run --voiceover
```

`prepare_generic_form_fixture.py` builds a project whose Customer form has no bridge area. The form has captions with inputs, a checkbox, two radio buttons, a drop-down list, a titled button, an untitled button with a help tip, an untitled button named `btnRefreshOrders`, one with 4D's default name `Button1`, an invisible button and Done. It also has a collection list box of four orders, whose Amount column the form renames Total when it loads and whose selection change is recorded, a tab control on every page that goes to a Details or a Notes page, a page subform with a search field and a Go button, and 4D Widgets' search picker. Its Notes page has a list box without a caption, whose twenty lines are more than it shows. Its Save button records the form's values. The AX run checks an unchanged window, the published objects, their labels and their states. It then writes both inputs, checks the checkbox, chooses a radio button and a drop-down item, selects a list box row, searches through the subform, types into the search picker, presses Refresh Orders and Save. The values Save records must match. It checks that the focused element follows 4D's focus from Name to City and the checkbox with Tab, back with Shift-Tab, and on through the radio buttons to the drop-down, Save and Help. It then presses the Notes tab, whose page replaces the Details page, checks that the page's list box without a caption is named Order Lines after its object, `lbOrderLines`, pages it down to its last line and back up, and presses the Details tab. The VoiceOver run types into the Name field, where it starts, as 4D focuses it, and presses Tab, after which VoiceOver reads City. It checks the checkbox with VO-Space and presses Tab until VoiceOver reads the Save button. It reads the list box as a table, enters it and moves to the next row, which is selected once, and presses Save. It reads the Notes tab by its label, presses it with VO-Space, reads the Order Lines table and scrolls it a page with Scroll down from VoiceOver's actions menu. Add `--compiled` or `--intel` for the other modes.

[Acceptance](../validation/generic-forms-development.json): the AX run passes interpreted and compiled, in native ARM and Rosetta, with an unchanged window; the VoiceOver run passes interpreted and compiled on ARM and compiled under Rosetta. Integrated fixtures keep the bridge's description.

Remaining scope: reading on past a list box's last drawn row without a page action, cell editing, tab controls, list subforms and the other kinds above; the keyboard focus 4D gives a field; 4D Server and remote clients; and 4D on Windows.
